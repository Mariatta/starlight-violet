# Changelog

## Unreleased

- A page whose body starts with a horizontal rule (`---` right under its front matter or its `# Title`) keeps everything up to the next rule. Before, the rendered page read that stretch as front matter and dropped it, or failed the build when it was not valid YAML.
- References in a work folder link: "Q3" (and "Q3 to Q9") to that question on the folder's handoff; "SPEC", "PLAN.md §6 and §6.4", "SPEC 3.2", "SPEC section 7" and "SPEC principle 2" to that page and section, for any capitalised page of the folder except README.md (a word prose writes in capitals anyway, such as TODO, NOTES or CLAUDE, links only as "TODO.md" or with a section); "task 1.2", "Stage 1" and "Stages 6 and 7" to that row of the plan's numbered table, whose rows now get anchors (`#task-1-2`, `#stage-1`). "Task 3" also matches with dotted numbers, and in lower case for a dotted number only ("task 1.2"), since "task 2" in a sentence is as often a count.
- A handoff's `blocks`, `answer` and `next_steps` are rendered as Markdown, like `question`, so their references link. They take inline Markdown only, as they were plain text before: the parser reads raw HTML in them as text, so a placeholder such as `<id>` is not lost, and a step written "1. Run the tests" stays text rather than becoming a list. A custom kind's `render` can ask for the same with `inline(text, { html: false })`; the `Inline` type is exported from `starlight-violet/kinds`.
- References link only to pages the site builds (the `skip` option and the landing page are left out), a page of another kind with `type: plan` is no plan, and "Task 1" and "task 1.2" use the folder's one plan. A question id also matches as "q3" in prose, though not in an address or a name ("?q3=foo", "q3.json", "Q3.json"), and Q1 to Q4 do not match as a quarter ("next Q4", "end of Q2", "Q3 revenue", "Q1 2027"); a reference inside a text directive's label (`:abbr[SPEC]`) is not linked; a numbered table in a handoff field gives its rows no anchors, so they never repeat the body's; a page naming itself ("SPEC" in SPEC.md) is not linked, though its sections are; on a split page a section is found on its own part, its `#` title included; and a count or length of time after a number ("the Task 3 times", "Stage 2 days later") keeps it text.
- Headings, tables and plan parts are read as the site's parser reads the page, with the Markdown features (math, smart punctuation) the site ends up with once every integration has set up, so section and row links match the page. A plan's task and PR headings follow from that: a heading inside a quote, a list item or a `:::` block is an example, not one of the plan's own, and on a split page a `# PR 2` heading inside one does not start a part (when the plan lists that PR, the build fails and says where its heading is, rather than leaving its address missing). Setext headings (a line underlined with `===`) count too.
- A question with an empty `answer` reads as open in `::questions`, as it does in the handoff's header.
- A task's or PR's title taken from its heading reads in `::tasks` and `::prs` as the heading is written: `` `code` `` stays code and an escape such as `\<br\>` stays text. Before, code marks were dropped, so `` `<details>` `` in a heading became a tag in the table.
- `::questions{of=...}` links each question's id to its row on that handoff, and its text reads as the handoff's own header reads it: references, relative links and `:task[3]` resolve from that handoff's folder, not the folder of the page showing the table, and a placeholder such as `<id>` in its blocks or answer is not lost.
- A handoff's next steps are numbered like Starlight's Steps (`sl-steps`); before, the list had a class no style matched.
- A reference inside emphasis inside a link (`[the **SPEC**](SPEC.md)`), or anywhere inside a reference-style link (`[SPEC][spec]`), is no longer linked a second time; only text directly in an inline link was skipped before.
- "Task 3" and "Stage 2" no longer link after "this", "that", "these", "those", "each", "every", "any", "which" or "what", so "run each Task 3 check twice" stays text, however many spaces or line breaks come between. 0.2.2 linked "Task 3" after any word.
- A file in a folder beside the notes whose name starts with the notes folder's (`notes-archive/` beside `notes/`) is no longer taken for a notes page, so a relative link to it is left as written rather than turned into an address the site does not have.

## 0.2.2 (2026-11-13)

- An `index.md` at the top of the notes folder is the site's landing page, so it can live with the notes instead of in the site's `src/content/docs/`. It needs no `kind`, and the `require` and `looseFiles` options leave it alone; it is not listed among the loose pages. Having both is an error naming the two files. Its front matter is read as if it were `src/content/docs/index.md`, so a hero image path is relative to that folder. A generated page (`extraPages`) at `index.md` is the landing page too.

## 0.2.1 (2026-11-12)

- Planning pages can live in any folder. A plan's topic is the folder that holds it, wherever it is, and pages directly in a top-level folder (`finance/PLAN.md`) have that folder as their topic. `topic=` in `:task`, `:pr`, `::prs`, `::tasks` and `::planning` finds the planning folder of that name anywhere in the notes, or takes its path when two folders share a name (the build names the page and both folders); for a plan whose pages declare no kind, it still finds the folder by path, or under `planning/` as before. `::topics` groups by folder and tells folders that share a name apart by path. A top folder holding only planning pages gets its own topics and recent changes on its section page, not just one named `planning`; `::topics` and `::planning` take `in=<folder>` for that. A subfolder inside a plan's folder (`planning/big/research/`) is now a topic of its own.
- The docs say plainly that the notes folder can have any name.

## 0.2.0 (2026-11-12)

- Progress bars: a plan's header shows tasks done and PRs merged as bars, `::planning` has a Progress column, and each PR page of a split plan shows the progress of its own tasks. `progressBar` is exported from `starlight-violet/kinds` for custom kinds.
- Source links: the `sourceLink` option (`'view'` or `'edit'`; it needs `github`) adds a link at the foot of each page to its Markdown file on GitHub, on the branch named by the new `github.branch` (default `main`). With `'view'`, Starlight's edit link reads "View source" (in English). Split plan pages link to the plan's file. Notes kept in another git checkout than the site get no link, with a warning. Generated pages and the guide pages never get an edit link now, `sourceLink` or not, since Starlight's would point at a file that does not exist.

## 0.1.0 (2026-11-11)

First release, as Violet (`starlight-violet`): the notes loader, the planning, reference, decision and handoff kinds, the page header, plans with tasks and PRs, shortcodes, heading links, the folder sidebar, the wide layout, the decisions page and the served-files route, split pages with previous and next links, and steps.
